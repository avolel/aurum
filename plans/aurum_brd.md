## 1. Executive Summary

Aurum is an AI-powered gold price intelligence platform that not only tracks real-time and historical gold price movements (XAU/USD) but explains **why** those movements happened, in plain language, backed by curated news from trusted financial sources.

This BRD translates the original Technical Design Document into business requirements while adopting a **cost-optimized delivery strategy**:

- **Free-first API sourcing.** Wherever a free tier or free public data source can satisfy a requirement (price feeds, macroeconomic data, news), it is the default. Paid providers are retained as documented upgrade paths, triggered only by user growth or data-quality thresholds.
- **Self-hosted AI via Ollama.** All LLM inference (causal explanations, summaries, sentiment, embeddings) runs on locally hosted open-weight models through Ollama, eliminating per-token API costs and keeping market data in-house.
- **A consolidated, containerized stack.** A single ASP.NET 10 Web API modular backend with PostgreSQL/EF Core replaces the original cloud-native microservices/Kafka architecture, and a single React Native Web codebase serves web, iOS, and Android — dramatically reducing build and run costs for the MVP phases.

The business goal is unchanged: existing tools show traders **what** happened to the gold price; Aurum tells them **why**.

## 3. Problem Statement

Gold market participants face a fragmented information landscape:

- Price feeds (Kitco, Bloomberg, TradingView) show movement but not context.
- News aggregators surface articles but do not connect them quantitatively to price changes.
- Analysis tools require expert interpretation and are inaccessible to non-specialists.
- No unified platform automatically correlates a price delta with its causal macroeconomic driver at the moment it happens.

Aurum closes this gap by combining live price feeds, a self-hosted LLM causation engine, and a news aggregation pipeline into a single platform — built on a lean, low-cost technology foundation.

## 4. Scope

### 4.1 In Scope

- Real-time and historical XAU/USD price tracking with delta detection across 1m, 5m, 15m, 1h, 4h, and 1D windows.
- AI-generated causal explanations for significant price movements, with multi-factor attribution, confidence scoring, and source citations — generated by locally hosted models via Ollama.
- Aggregation, deduplication, relevance filtering, topic tagging, and sentiment scoring of gold-related news from free RSS feeds and free-tier news APIs.
- Macroeconomic context ingestion (CPI, PCE, NFP, Fed Funds Rate, Treasury yields, dollar index, VIX proxy) from free government and public data sources.
- User accounts, watchlist-style alerts, push/email notifications, and AI-generated daily/weekly digests.
- Web, iOS, and Android clients from a single React Native Web codebase.
- Public REST + real-time (SignalR/WebSocket) API with tiered rate limits.
- Docker-based deployment of all services, databases, and the Ollama inference runtime.

### 4.2 Out of Scope (This Release)

- Multi-metal support (silver, platinum, palladium) — deferred to Phase 6.
- Price forecasting / predictive signals (Aurum explains, it does not predict).
- Bloomberg Terminal integration, co-location, and white-label offerings (Phase 7).
- Enterprise price feeds (Refinitiv/LSEG) — documented as a paid upgrade path only.
- Trading execution, brokerage integration, or any buy/sell functionality.
- Native Swift/SwiftUI and Kotlin/Compose apps (replaced by React Native).

## 7. Functional Requirements

### 7.1 Price Tracking & Delta Detection

- FR-1.1 Poll the primary free price source at the maximum cadence its free tier allows; cache the latest quote server-side and fan out to clients via SignalR.
- FR-1.2 Normalize all quotes to a canonical tick format: timestamp, bid, ask, mid, source.
- FR-1.3 Automatic failover across at least three configured providers (free tiers ordered by quality; paid tier as final fallback if enabled).
- FR-1.4 Compute rolling deltas over 1m/5m/15m/1h/4h/1D windows; classify significant events with direction, magnitude, velocity, and volatility metadata.
- FR-1.5 Store ticks in PostgreSQL (optionally with the TimescaleDB extension) with daily partitioning and the retention policy in §11.

### 7.2 AI Causation Engine (Ollama)

- FR-2.1 On each significant price event, assemble context: macro events (4-hour lookback), gold-relevant news (8-hour lookback), and current dollar index, 10Y yield, and volatility levels.
- FR-2.2 Run semantic retrieval of historically similar price movements from a knowledge base stored in PostgreSQL with the **pgvector** extension (replacing FAISS), using embeddings generated by an Ollama embedding model (e.g., nomic-embed-text).
- FR-2.3 Generate the causal explanation with a locally hosted reasoning model via Ollama (e.g., a Llama 3.x or Qwen-class instruct model), producing: probable cause(s), per-factor confidence percentages, a 2–4 sentence explanation, and 3–5 supporting headlines.
- FR-2.4 Validate output with a second, lighter Ollama model pass (factual grounding, source alignment, coherence, recency). Low-scoring outputs are flagged "Awaiting Confirmation."
- FR-2.5 Attribute movements to the causal taxonomy: Fed/Monetary Policy, Inflation Data, USD Strength, Treasury Yields, Geopolitical Risk, Central Bank Buying, Risk Appetite, Macro Surprises, Technical Breakouts, ETF Flows.
- FR-2.6 Persist explanations in PostgreSQL via EF Core with model name/version recorded for auditability.

Model strategy (all via Ollama, roles replacing the TDD's cloud LLM lineup):

| Role | Model Class (Ollama) | Replaces (TDD) |
| --- | --- | --- |
| Primary causation & digests | Large open-weight instruct model (e.g., Llama 3.x 70B-class or Qwen-class, per available hardware) | Claude 3 Opus / GPT-4o |
| Validation pass | Mid-size instruct model | Claude 3 Sonnet |
| Quick summaries / low latency | Small instruct model (7–8B class) | Claude 3 Haiku |
| News relevance & topic tagging | Small instruct model with structured (JSON) prompting | Fine-tuned BERT |
| Sentiment scoring | Small instruct model with structured prompting (optional: locally run FinBERT if later approved) | FinBERT |
| Embeddings | Ollama embedding model (e.g., nomic-embed-text) | text-embedding-3-large |

### 7.3 News Aggregation & Source Intelligence

- FR-3.1 Ingest articles on a scheduled basis (background hosted services in the ASP.NET application) from the free-first source list in §9.3.
- FR-3.2 Deduplicate via content fingerprinting (SimHash) stored as content_hash.
- FR-3.3 Score each article for gold relevance (0.0–1.0): below 0.60 archived; 0.60–0.80 background context; above 0.80 promoted to the Active News Feed.
- FR-3.4 Tag articles with topic labels: MONETARY_POLICY, INFLATION, GEOPOLITICS, CENTRAL_BANKS, TECHNICALS, ETF_FLOWS, CURRENCY, DEMAND_SUPPLY.
- FR-3.5 Assign BULLISH/NEUTRAL/BEARISH sentiment; aggregate into an hourly Sentiment Index; raise a "Conflicting Signals" flag when sentiment diverges from price direction.
- FR-3.6 Maintain per-source Trust Scores weighted by editorial independence (30%), track-record accuracy (25%), institutional recognition (20%), transparency (15%), and freshness (10%).
- FR-3.7 Respect each source's terms of service; only headline, link, snippet, and metadata are stored for display, with full attribution and outbound links.

### 7.4 Alerts, Digests & Notifications

- FR-4.1 Users can create alerts on price thresholds, percentage moves, and new explanations matching selected causal factors.
- FR-4.2 Delivery via push notification (React Native) and email; alert history retained per user.
- FR-4.3 AI daily digest (narrative briefing, top 3 stories, factor summary) and weekly summary generated by the Ollama pipeline.

### 7.5 User Management & API Platform

- FR-5.1 Account registration, JWT authentication, profile, notification preferences, and personal API key management.
- FR-5.2 REST endpoints mirroring the TDD specification (live price, history, events, explanations, news, macro snapshot, sentiment, alerts, digests) under /v1.
- FR-5.3 Real-time channels via SignalR (WebSocket transport): price ticks, price events, explanation-ready, high-relevance news, macro updates.
- FR-5.4 Tiered rate limiting: Free (30 req/min, delayed stream, 30-day history), Starter $29/mo (300 req/min, 1-year history), Pro $99/mo (1,000 req/min, real-time, 5-year history), Enterprise (custom).

### 7.6 Client Applications (React Native Web)

- FR-6.1 One codebase targeting Web (react-native-web), iOS, and Android.
- FR-6.2 Core screens: Live Dashboard, Explanation Feed, News Intelligence, Historical Explorer, Macro Pulse, Alerts Manager, Daily Digest, Settings/Profile.
- FR-6.3 Real-time data via SignalR client; progressive loading (price first, explanations streamed in).
- FR-6.4 Performance targets: First Contentful Paint < 1.5s (web); smooth 60fps charting via a canvas-based charting library compatible with React Native Web.

### 9.4 AI Cost Position

| Item | Original TDD Approach | BRD Approach | Cost Impact |
| --- | --- | --- | --- |
| Explanation generation | Claude 3 Opus / GPT-4o API | Ollama-hosted open-weight model | Per-token fees → $0 (hardware only) |
| Validation | Claude 3 Sonnet API | Ollama mid-size model | $0 marginal |
| Summaries | Claude 3 Haiku API | Ollama small model | $0 marginal |
| Embeddings | text-embedding-3-large API | Ollama embedding model + pgvector | $0 marginal |
| Vector search | FAISS service | pgvector in PostgreSQL | One less service to run |

The trade-off — accepted by the business — is that self-hosted open-weight models may produce lower explanation quality than frontier hosted models. Mitigations: the validation pass (FR-2.4), the "Awaiting Confirmation" state, the user flagging loop (BR-14), and a quarterly model-refresh review as stronger open-weight models are released.

## 12. Assumptions

- Free-tier request quotas, combined with server-side caching and a fan-out architecture (one upstream poll serves all users), are sufficient for MVP traffic.
- A single GPU-capable server can meet the 5-minute explanation SLA for expected MVP event volume (roughly dozens of significant events per trading day).
- RSS feeds of the listed publishers remain publicly available and permit headline/link aggregation with attribution.
- ASP.NET 10 and EF Core current releases are production-ready at build time.
- React Native Web can deliver the required charting performance; a canvas-based chart library will be validated in a Phase 0 spike.
- Some free tiers (e.g., API Ninjas) restrict commercial use; Legal will confirm terms per provider before public launch, and providers whose terms block commercial use will be upgraded to paid or swapped.

## 13. Constraints

- Technology stack is fixed: ASP.NET 10 Web API, PostgreSQL, EF Core, React Native Web, Docker, Ollama.
- No external hosted LLM APIs for production inference.
- Third-party data budget at launch: $0/month; paid APIs permitted post-launch when justified by growth or quality triggers documented in §10.
- Aurum provides no financial advice, price targets, or buy/sell signals; the disclaimer framework from the TDD is retained verbatim.

## 14. Risks & Mitigations

| Risk | Impact | Likelihood | Mitigation |
| --- | --- | --- | --- |
| Free API quota exhaustion or provider shutdown | Price feed gaps | Medium | Three-provider failover chain; aggressive caching; documented paid upgrade path |
| Open-weight model explanation quality below expectations | User trust | Medium | Validation pass, confidence scoring, "Awaiting Confirmation" state, user flagging, quarterly model review |
| Free-tier commercial-use restrictions | Legal exposure | Medium | Per-provider terms review before launch; budget line for first paid upgrades |
| Delayed (15-min) secondary data misleading users | Trust/accuracy | Low | Always label data freshness and source per quote in the UI and API |
| RSS feed structure changes | News gaps | Medium | Per-source parser isolation, monitoring, and alerting on ingestion failures |
| Ollama hardware bottleneck during volatile markets (event bursts) | SLA misses | Medium | Priority queue (explanations before digests); small-model fallback; horizontal Ollama workers |
| Single-database contention (PostgreSQL doing relational + time-series + search + vectors) | Performance | Medium | TimescaleDB extension, partitioning, and read replicas; split stores only if metrics demand |
